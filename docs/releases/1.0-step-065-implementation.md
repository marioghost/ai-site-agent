## Canonical registry design

- **Location:** `backend/app/services/feature_flags.py`
- **Structure:** frozen `FlagDefinition` dataclass + `FLAG_DEFINITIONS: tuple[FlagDefinition, ...]`
- **Fields used:** `key`, `source`, `default`, `classification`, `friendly_name`, `effect`, `rollout`, `runtime_owner`, `config_attr` / `settings_attr`, `product_visibility`, `engineering_visibility`, `value_kind`, `int_default`
- **Helpers preserved** as effective-value owners for KOS/Settings flags
- **No** remote platform, DB registry, plugins, percentage rollout, or circular imports
- Build-info imports `env_bool_flag_definitions` / `settings_flag_definitions` / `maintenance_observation` — `_ENV_CAPABILITIES` / `_SETTINGS_CAPABILITIES` removed

### Maintenance budget JSON shape (chosen)

Additive nested object on `GET /api/build`:

```json
"maintenance_observation": {
  "execution_enabled": true,
  "investigations_per_cycle": 0,
  "surface": "env",
  "runtime_owner": "maintenance_orchestration"
}
```

- `investigations_per_cycle` is **int**
- Not inserted into `env_flags: dict[str, bool]`
- `MAINTENANCE_EXECUTION_ENABLED` is also reflected as bool in `env_flags` / `deployed_capabilities` (additive relative to pre-065 bool maps)

Schema: `MaintenanceObservation` in `backend/app/schemas/build_info.py`; optional TS `maintenance_observation?` on `BuildInfo`.

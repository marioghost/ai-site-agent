# Release 0.4 — Step 031: Auto `memory_version` bump on shadow integrate

**RFC-100 Step 031**  
**Lifecycle state:** Implementation → Engineering Ready (after review)

## Summary

Hardens and documents the **single automatic** `memory_version` bump path introduced in Step 030. No second bump mechanism. Shadow claim integration remains passive — Epistemic Memory is **not** used for reasoning or retrieval.

## What Step 031 adds

| Item | Path |
|------|------|
| Deferred-commit bump | `MemoryVersionService.bump(commit=False)` |
| Single auto-bump owner | `EpistemicMemoryIntegrationService._bump_after_successful_shadow_persist()` |
| Bump contract tests | `backend/tests/test_epistemic_shadow_memory_version_bump.py` |
| Documentation | `docs/MEMORY_VERSION.md` (auto-bump section) |

## When `memory_version` bumps

Only when **all** of the following are true:

1. `memory_shadow_write_enabled=true`
2. `ClaimExtractionFromSI` returns non-empty proposals
3. `EpistemicMemoryService.persist_claim_proposals()` completes successfully
4. At least one **new** row was created (`ShadowPersistResult.any_created`)

Then `MemoryVersionService.bump(commit=False)` runs — the increment shares the caller DB transaction and commits with the SI batch / indexing save.

## When it does **not** bump

| Condition | Bump |
|-----------|------|
| Flag OFF | No |
| Empty proposals | No |
| Idempotent re-run (no new rows) | No |
| Persist raises / partial failure | No |
| Caller transaction rolls back | No (deferred commit) |

Manual admin bump (`POST /api/settings/memory-version/bump`) remains separate and uses `bump(commit=True)`.

## Relationship to `cache_namespace_v2_enabled`

- **Flag OFF (default):** `memory_version` changes do **not** affect cache namespace hashes. Shadow writes collect data without invalidating production caches.
- **Flag ON:** namespace hash includes `memory_version` via `MemoryVersionService.get()`. Auto-bump on new shadow rows will cause cache miss on next lookup — required before memory-assisted evidence can safely influence cached answers.

See [MEMORY_VERSION.md](../MEMORY_VERSION.md) and [FEATURE_FLAGS.md](../FEATURE_FLAGS.md).

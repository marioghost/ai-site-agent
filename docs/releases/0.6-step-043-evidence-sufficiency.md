# Release 0.6 — Step 043: Evidence sufficiency (advisory)

**RFC-100 Step 043**  
**Lifecycle state:** Implementation → Engineering Ready (after review)

## Summary

Introduces **source-scoped evidence sufficiency** inside `ReasoningService`.
Assessment is advisory/shadow-only: typed fields + additive diagnostics.
**Final answer, sources, prompts, LLM, and streaming protocol are unchanged.**

## Semantic rule

Sufficiency ≠ world-truth confidence. It asks only whether available **website**
evidence appears sufficient for the requested response.

## Delivered

| Item | Path |
|------|------|
| Assessor | `backend/app/services/reasoning/evidence_sufficiency.py` |
| Wiring | `ReasoningService._wrap` / stream final stamp |
| Diagnostics | `reasoning_diagnostics.evidence_sufficiency` on `RagResult` |
| Tests | `backend/tests/test_evidence_sufficiency.py` |
| Docs | `docs/REASONING_SERVICE.md` |

## Contract fields

- `evidence_sufficient`: `true` \| `false` \| `null` (unknown)
- `sufficiency_status`: `sufficient` \| `insufficient` \| `unknown`
- `sufficiency_reasons`, `evidence_count`, `independent_source_count`
- `completeness_risk`, `missing_evidence_hint`

## v1 signals (deterministic)

| Signal | Outcome |
|--------|---------|
| No sources / `used_context=false` | insufficient |
| Empty source URLs | insufficient |
| Ambiguous / clarification intent | unknown |
| List / overview without completeness | unknown + `completeness_risk` |
| Narrow factual with provenance | sufficient (advisory) |

## Non-goals

- No speech-act change; no refuse/clarify/qualify
- No Epistemic Memory; no tensions; no version bumps
- No extra retrieval/LLM; no score-as-sufficiency
- No industry/customer hardcoding

## 1. Current architecture audit

### 1.1 CanonicalSourceService (legacy doc-type path)

**PROVEN BY CURRENT CODE** — `backend/app/services/canonical_source_service.py`:

| Method | Production use |
|--------|----------------|
| `select_context` (~32–76) | **Yes** — only production caller |
| `context_for_llm` | No external callers |
| `needs_canonical_fallback` | No callers |
| `merge_hits` | No callers (RPS has its own merge) |

**Doc-type path behavior (`select_context`):**

1. If `enable_canonical_source_selection` is false → return `hits[:top_k]` unchanged.
2. Else load KP `SourcePriorityRule` boost/deprioritize document types for intent.
3. Mark `hit.is_canonical` from preferred document types.
4. Overview + news deprioritization may exclude “noisy” types and prefer canonical pool.
5. Else reorder: canonical first, then by score.

### 1.2 Call site

**PROVEN BY CURRENT CODE** — `RetrievalPipelineService.finalize_pipeline` (~403–406):

```
assemble_evidence (DFP / DocumentScorer)
  → optional broad inject
  → ★ CanonicalSourceService.select_context   ← doc-type injection
  → bilingual dedupe
  → ContextBuilder
```

**Reasoning** (`reasoning_service.py` ~190–213) orders: prepare → Memory assist → assemble → **finalize** (canonical still inside finalize) → **then** `MemoryCanonicalShadowComparator`.

**Evidence Assembly** does not call CanonicalSourceService.

### 1.3 Existing kill-switch (not Memory-aware)

| Flag | Default | Effect |
|------|---------|--------|
| `enable_canonical_source_selection` | **true** | Disables entire `select_context` reorder when false |
| `enable_news_deprioritization_for_overview_queries` | true | Partial (news branch only) |

`enable_canonical_source_selection` is already hashed into retrieval cache namespace (**PROVEN** — `cache_namespace_service.py`).

### 1.4 What “memory canonical” is today

**PROVEN BY CURRENT CODE + Step 048 docs:**

| Component | Role |
|-----------|------|
| `memory_canonical_shadow_enabled` | Settings flag; default **false** |
| `memory_canonical_shadow_effective` | Requires Reasoning + assist + cache v2 + shadow flag |
| `MemoryCanonicalShadowComparator` | **Set-compare diagnostics only** — no retrieval, no ranking, no answer influence |

Shadow runs **after** finalize. It does **not** replace CanonicalSourceService.

**MIG-012** goal was: parallel pick from claim authority + **compare in diagnostics** — delivered as Step 048 shadow, **not** as active Memory authority selection.

### 1.5 Gap summary

| Expected by Step 055 title | Reality at baseline |
|----------------------------|---------------------|
| Disable doc-type path when “memory canonical on” | No such gate exists |
| A dedicated migration flag | No Step 055 flag name in `FEATURE_FLAGS.md` planned table |
| Memory picks context | **Not implemented** — assist is advisory; shadow is diagnostic |
| Couples shadow ON → behavior change | Would **violate** Step 048 / MIG-012 diagnostic-only contract |

## 2. RFC intent for Step 055

**REQUIRED BY RFC-100** (§ Release 0.8):

| Step | Title | Detail |
|------|-------|--------|
| **055** | CanonicalSourceService: disable doc-type path when memory canonical on | Flag |

Related:

- **MIG-012** — shadow compare (`memory_canonical_shadow_enabled`) — **already implemented** (048)
- Architecture v1 / roadmap — eventually **replace** CanonicalSourceService with Memory authority + Reasoning (“No doc-type canonical”)
- Snapshot debt — RPS finalize still owns canonical; called out for 0.8 / Step 055

**PROPOSED MINIMAL INTERPRETATION of sparse “Flag” detail (approved):**

Introduce a **new Settings-backed flag** that gates the KP **doc-type reorder** in `CanonicalSourceService.select_context` / RPS finalize, without implementing Memory authority selection, and **without** reusing `memory_canonical_shadow_enabled` as a behavior gate.

### Final flag name (locked)

| Name | Status |
|------|--------|
| **`legacy_doc_type_canonical_enabled`** | **Approved — use this** |
| `legacy_canonical_selection_enabled` | Acceptable alternative only if implementation constraints require |
| `disable_canonical_doc_type_path` | **Rejected** — negative naming |
| `memory_canonical_authority_enabled` | **Rejected** — implies Memory already owns selection |

### Semantics

| Value | Behavior |
|-------|----------|
| **`true`** | Current legacy `CanonicalSourceService` doc-type reorder **runs** (subject to existing `enable_canonical_source_selection`) |
| **`false` (default)** | **Skip** the legacy doc-type reorder |

Rationale: positive name describing the **legacy mechanism itself**; accurate and future-proof; does not claim Memory authority.

Reuse of `enable_canonical_source_selection=false` alone remains insufficient for Step identity (no Knowledge OS migration flag).

## 3. Existing implementation gaps

1. **No active Memory canonical selector** — cannot literally “switch to Memory canonical” yet.
2. **Shadow ≠ authority** — turning shadow ON must remain answer-neutral.
3. **Assist ≠ context rewrite** — `MemoryAssistPolicy` does not replace hit order for the LLM.
4. **Dead CanonicalSourceService helpers** — `context_for_llm` / `needs_canonical_fallback` / `merge_hits` unused; cleanup is **DEFERRED**.
5. **No Step 055 flag registered** in FEATURE_FLAGS planned list.
6. **Dual gates risk** — new flag + existing `enable_canonical_source_selection` need a clear precedence story.

## 9. Recommended option

**Option A** — **APPROVED** with locked flag name

1. Add Settings boolean **`legacy_doc_type_canonical_enabled`**, default **`false`**, Alembic additive migration (next free after `0018`).
2. When the flag is **`false`**, skip KP doc-type reorder (same runtime effect as `enable_canonical_source_selection=false` for `select_context`).
3. When the flag is **`true`**, preserve current legacy doc-type reorder (still subject to `enable_canonical_source_selection`).
4. **Do not** key behavior off `memory_canonical_shadow_enabled` alone.
5. **Do not** implement Memory context selection.
6. Include flag in retrieval cache namespace (like existing canonical enable flag).
7. Expose via Settings API + FEATURE_FLAGS + build/migration flags panel (read-only).
8. Keep shadow comparator unchanged (compares whatever finalize produced).

**Precedence (approved):**

```
if not enable_canonical_source_selection:
    skip doc-type path
elif not legacy_doc_type_canonical_enabled:
    skip doc-type path
else:
    select_context as today
```

Equivalent: doc-type reorder runs only when **both** `enable_canonical_source_selection` and `legacy_doc_type_canonical_enabled` are true.

**Default-OFF consequence:** After migration `server_default=false`, existing Settings rows resolve to **false** → legacy doc-type path **off** once the release is deployed and migrated. That is intentional for Step 055. Rollback is Settings PUT `legacy_doc_type_canonical_enabled=true` (not “flip a disable flag off”).

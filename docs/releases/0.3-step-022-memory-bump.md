# RFC-100 Step 022 — Manual memory version bump (operational stub)

**Release track:** 0.3  
**Status:** API-only; no dashboard UI required.

## Purpose

Operators can bump `memory_version` manually before automatic claim/memory bumps exist (Step 031+). This validates the revision counter and prepares for cache namespace v2 (Step 023).

## Endpoint

| | |
|---|---|
| **Method** | `POST` |
| **Path** | `/api/settings/memory-version/bump` |
| **Auth** | Admin only (`require_admin`) |
| **Body** | Optional `{ "reason": "string" }` (max 500 chars, not persisted) |

### Example

```bash
curl -X POST http://localhost:8000/api/settings/memory-version/bump \
  -H "Authorization: Bearer $ADMIN_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"reason": "pre-release smoke test"}'
```

### Response

```json
{
  "previous_memory_version": 1,
  "new_memory_version": 2,
  "reason": "pre-release smoke test"
}
```

Default `reason` when omitted: `manual_admin_stub`.

## What it does not do

- No cache invalidation (until Step 023 `cache_namespace_v2_enabled`)
- No chat, retrieval, or Executive changes
- No automatic bumps from claims or consolidation

## Future

Step **031** will call `MemoryVersionService.bump()` on shadow claim integrate. This manual endpoint stays available for operational overrides.

See [MEMORY_VERSION.md](../MEMORY_VERSION.md).

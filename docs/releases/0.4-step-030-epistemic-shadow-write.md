# Release 0.4 — Step 030: Epistemic Memory shadow writes

**RFC-100 Step 030**  
**Lifecycle state:** Implementation → Engineering Ready (after review)

## Summary

First epistemic persistence step — **passive shadow writes only**. When `memory_shadow_write_enabled=true`, claim proposals from Source Intelligence are persisted idempotently after SI generation. **Epistemic Memory is not used for reasoning or retrieval.**

## Delivered

| Item | Path |
|------|------|
| Flag migration | `backend/migrations/versions/0015_memory_shadow_write_enabled.py` |
| Write API | `EpistemicMemoryService.persist_claim_proposals()` |
| Write impl | `backend/app/services/epistemic_memory/epistemic_memory_write_service.py` |
| Integration | `backend/app/services/epistemic_memory/memory_integration_service.py` |
| SI hook | `SourceIntelligenceGenerationService`, inline indexing path |
| Tests | `backend/tests/test_epistemic_memory_shadow_write.py` |

## Flag

| Setting | Default | Effect |
|---------|---------|--------|
| `memory_shadow_write_enabled` | **false** | When false: zero epistemic writes, zero `memory_version` bumps |

## Behavior when ON

1. Post-SI: `ClaimExtractionFromSI` → in-memory proposals
2. `EpistemicMemoryIntegrationService` → `EpistemicMemoryService.persist_claim_proposals()`
3. Idempotent observation / claim / evidence rows
4. `MemoryVersionService.bump()` **only** if at least one new row created

## Explicit non-goals

- No merge, supersession, conflict resolution, belief revision
- No chat/retrieval/cache/Executive/dashboard changes
- No automatic bump on no-op re-runs (verified Step 031)

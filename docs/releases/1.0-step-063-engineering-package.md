# 1. Step Overview

## 1.1 Purpose

**REQUIRED BY RFC-100 (Release 1.0 / Step 063):** Make the Knowledge OS runtime path the **default** posture for Release 1.0 by flipping Knowledge OS migration flags from default **OFF** → default **ON**.

Product meaning (RFC-101 language): Ask and related Knowledge OS behavior “just work” without operators manually enabling migration flags. Engineering Mode remains the place to inspect flag state (`Build & flags`).

## 1.2 Scope

**LOCKED DECISION — flags default ON:**

| Surface | Flag / setting | Default after Step 063 |
|---------|----------------|------------------------|
| Env | `KNOWLEDGE_OS_EXECUTIVE_ENABLED` | **true** (unset → true) |
| Env | `REASONING_SERVICE_ENABLED` | **true** (unset → true) |
| Env | `EVIDENCE_ASSEMBLY_ENABLED` | **true** (unset → true) |
| Env | `REASONING_SPEECH_ACTS_ENABLED` | **true** (unset → true) |

| Settings DB | `enable_semantic_diagnostics_v2` | **true** |
| Settings DB | `cache_namespace_v2_enabled` | **true** |
| Settings DB | `memory_shadow_write_enabled` | **true** |
| Settings DB | `memory_evidence_assist_enabled` | **true** |
| Settings DB | `memory_canonical_shadow_enabled` | **true** |

**LOCKED DECISION — accompanying engineering metadata (non-product):**

- Alembic migration that sets `server_default=true` and `UPDATE`s existing settings rows for the five Settings flags above.
- `BuildInfoService` / `/api/build` reflects capability **defaults** and marks Release **1.0 in progress** without closing Release 1.0 (`APP_RELEASE` remains last accepted release until Step 067 / GA closure policy).
- Update `docs/FEATURE_FLAGS.md` kill-switch language: **unset no longer disables** env flags; kill-switch is explicit `false` + restart.

**LOCKED DECISION — maintenance safety:**

- `MAINTENANCE_EXECUTION_ENABLED` may default ON when unset.
- `MAINTENANCE_INVESTIGATIONS_PER_CYCLE` (budget) remains default **0** → **no investigation work** until budget is explicitly configured.
- Therefore default ON for the maintenance flag alone does **not** execute maintenance.

# 11. Rollback strategy

## Can roll back (ops, no code redeploy for Settings)

| Lever | Effect |
|-------|--------|
| Set any KOS env flag `false` + restart | Disables that seam |
| Set Settings column `false` | Disables Settings-backed capability |
| Set `MAINTENANCE_EXECUTION_ENABLED=false` | Disables maintenance execution |
| Keep budget at 0 | Ensures no maintenance work even if flag ON |

## Can roll back (deploy)

| Lever | Effect |
|-------|--------|
| Redeploy prior release artifact | Restores prior defaults + code |
| Alembic downgrade `0020` | Restores `server_default=false` only |

## Cannot / must not assume

| Item | Why |
|------|-----|
| Unset env disables flag | **False after Step 063** — unset means ON |
| Downgrade resets row values to false | Downgrade does **not** `UPDATE` rows back |
| Rollback removes Speech/Reasoning code | Code remains; flags only |
| Product Settings UI to flip flags | Forbidden by RFC-101 |

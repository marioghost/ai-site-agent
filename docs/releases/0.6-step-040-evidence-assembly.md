# Release 0.6 — Step 040: EvidenceAssemblyService (DFP wrap)

**RFC-100 Step 040**  
**Lifecycle state:** Implementation → Engineering Ready (after review)

## Summary

Introduces `EvidenceAssemblyService` as a **stateless passthrough facade** over
`DocumentFirstRetrievalPipeline`. Establishes evidence-assembly ownership and a
migration seam. **Default flag OFF** — production retrieval path unchanged.

## Delivered

| Item | Path |
|------|------|
| Service | `backend/app/services/evidence_assembly/` |
| Flag | `EVIDENCE_ASSEMBLY_ENABLED` (default false) |
| Wiring | `RetrievalPipelineService` DFP stage only |
| Marker | `evidence_assembly_path` on `RetrievalDiagnostics` / `DocumentRetrievalResult` |
| Tests | `backend/tests/test_evidence_assembly_service.py` |
| Docs | `docs/EVIDENCE_ASSEMBLY.md` |

## Flag matrix (DFP stage)

| `EVIDENCE_ASSEMBLY_ENABLED` | DFP stage |
|-----------------------------|-----------|
| OFF | `RetrievalPipelineService` → `DocumentFirstRetrievalPipeline` |
| ON | `RetrievalPipelineService` → `EvidenceAssemblyService` → DFP |

Upstream Executive / Reasoning flags unchanged from Step 039.

## Non-goals (this step)

- No move of RPS intent / expansion / canonical / broad / context builder
- No Reasoning → EA direct calls
- No prompt / LLM / streaming / answer-text changes
- No Epistemic Memory
- No duplicate `DocumentRetrievalResult` DTO
- Flag not default ON

## Performance

| Concern | Step 040 impact |
|---------|-----------------|
| Dispatch overhead | One extra Python call when flag ON |
| Object allocation | One `EvidenceAssemblyRequest` when ON |
| Context copying | None added |
| Retrieval calls | **Exactly one** DFP run |
| LLM / tokens | **None** |

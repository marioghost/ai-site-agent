# 2. Step Contract

## 2.1 Purpose

**REQUIRED BY RFC-100 (Release 1.0 / Step 064):** Remove the legacy **direct** `RagService` / `RagStreamingService` path from chat API dispatch, while **keeping** the emergency Executive environment variable.

**LOCKED DECISION — primary outcome:**

```text
Ask
→ POST /api/chat | /api/chat/stream
→ evaluate Executive emergency gate
→ if Executive explicitly disabled → controlled unavailable
→ else ExecutiveService only
→ ReasoningService (when enabled) OR Executive-owned internal Rag degrade
→ Evidence Assembly / retrieval / Language
→ response
```

The API layer must **not** choose among Executive / Reasoning / Rag as peer top-level engines.

# 4. Routing Contract

**LOCKED DECISION — both routes:**

```text
API route
→ resolve session / concurrency (existing)
→ evaluate knowledge_os_executive_enabled()
→ if explicitly False:
     log path=executive_disabled
     controlled unavailable (no Executive/Reasoning/Rag/retrieval started)
→ else:
     log path=executive
     ExecutiveService only (answer | answer_stream)
```

| Mode | Behavior |
|------|----------|
| Non-stream | Gate → Executive.answer → builder → session persist (existing) |
| Stream | Gate → Executive.answer_stream → SSE (existing final/error/[DONE]) |
| Cancellation | Preserve existing `GeneratorExit` / cancel logging |
| Timeout | Preserve existing timeout/error contracts; **no** second execution path |
| Propagation | request_id, session, sources, diagnostics — existing |

**LOCKED DECISION:** After Step 064 the API layer does **not** branch on Reasoning or Rag flags for top-level engine selection. Those flags are evaluated **inside** Executive / Reasoning only.

# 5. Emergency Environment Contract

**REQUIRED BY RFC-100 title:** keep emergency env.

**LOCKED DECISION — meaning of `KNOWLEDGE_OS_EXECUTIVE_ENABLED=false`:**

| Rule | Requirement |
|------|-------------|
| No silent direct Rag | **Mandatory** |
| No direct Reasoning | **Mandatory** |
| Controlled, observable failure | **Mandatory** |
| No retrieval / Reasoning / EA / Rag work started by API | **Mandatory** |
| Env var retained (not decorative, not removed) | **Mandatory** |
| Unset / true | Canonical Executive entry (Step 063 default ON) |

### 5.1 Non-stream (LOCKED)

| Field | Value |
|-------|--------|
| HTTP status | **503** Service Unavailable |
| Body | FastAPI/`HTTPException` detail — stable operator-facing string identifying **Executive path disabled by operator** (exact copy frozen at implementation as a single constant; no stack traces; no secrets) |
| Logging | `chat_dispatch` with `path=executive_disabled` **before** any orchestration |
| Fallback | **None** |

### 5.2 Stream (LOCKED)

| Field | Value |
|-------|--------|
| Behavior | Emit one SSE `error` event using existing envelope shape (`error_type`, `message`, `partial_diagnostics`) |
| `error_type` | **`executive_disabled`** |
| `message` | Same operator-disabled meaning as non-stream (aligned copy) |
| Close | End stream cleanly (no further token/final events; no second engine) |
| Logging | `path=executive_disabled`, `stream_lifecycle=error` (or start+error parity with existing patterns) |
| Fallback | **None** |

### 5.3 Rejected interpretations (LOCKED)

| Rejected | Why |
|----------|-----|
| Executive false → direct Rag | Violates “remove legacy direct path” |
| Executive false + Reasoning true → direct Reasoning | Violates sole Executive entry |
| Ignore false / force Executive | Makes emergency env decorative |
| Auto-fallback to Rag after Executive failure | Reintroduces dual engines |
| New emergency endpoint / engine | Scope creep / RFC-101 dual-engine risk |

# 6. Internal Degradation Contract

**LOCKED DECISION — distinguish removed vs retained:**

| Removed (API) | Retained (inside Executive) |
|---------------|----------------------------|
| `api/chat.py` → `RagService` | `ExecutiveService` → `ReasoningService` when Reasoning **enabled** |
| `api/chat.py` → `RagStreamingService` | `ExecutiveService` → internal `RagService` / `RagStreamingService` when Reasoning **explicitly disabled** |
| `api/chat.py` → `ReasoningService` | Rag as Language/cache/finalize under Reasoning |

**PROVEN BY CURRENT ARCHITECTURE:** `ExecutiveService.answer` / `answer_stream` already implement Reasoning-gated vs Rag passthrough (`backend/app/services/executive/executive_service.py`). **Do not redesign** unless a correctness bug is proven during implementation.

**LOCKED DECISION:** Reasoning=`false` does **not** bypass Executive at the API. Executive remains the sole entry and owns degraded Rag.

# 7. Failure Contract

| Scenario | Locked behavior |
|----------|-----------------|
| Executive explicitly disabled | §5 controlled unavailable; no fallback |
| Executive startup/execution failure | Preserve existing API/SSE error contracts where possible; **never** silent API→Rag; log via existing standards; no secrets; no retry queue / alternate worker |
| Reasoning disabled | Executive owns degraded internal Rag (§6) |
| EA disabled or failed | Preserve existing Reasoning/Executive behavior; no API legacy fallback |
| Empty evidence | Preserve clarify/refuse/qualify/answer; no second engine |
| Streaming cancellation | Preserve cleanup + cancel logging; no fallback after partial emission |
| Timeout | Preserve current contract; do not start a second path |
| Overloaded (429) | Unchanged concurrency path (still before/around Executive call as today) |

# Release 0.6 — Rollback procedures

**RFC-100 Release 0.6** (Steps 039–045)  
**Default runtime:** all migration flags **OFF** (legacy behavior)

Release 0.6 introduces **no new persistent cognitive data** in PostgreSQL or Qdrant when flags are OFF. Rollback is normally **flag- or code-level** only. **Do not** use `ai_site_agent_recovery` as a routine feature rollback — that database is incident rollback infrastructure only.

---

## Rollback levels (least → most disruptive)

### Level 1 — Disable speech-act Language UX

**When:** Clarify/refuse/qualify wording is undesirable but Reasoning diagnostics are acceptable.

```bash
REASONING_SPEECH_ACTS_ENABLED=false   # or unset
# restart backend
```

**Effect:** Reasoning ON returns to Step 044 advisory-only (answer text unchanged). Reasoning OFF ignores this flag entirely.

**Database:** No change required.

---

### Level 2 — Disable Reasoning seam

**When:** Any Reasoning-path regression (sufficiency, speech-act diagnostics, coordinator).

```bash
REASONING_SERVICE_ENABLED=false
REASONING_SPEECH_ACTS_ENABLED=false   # redundant but explicit
# restart backend
```

**Effect:** Chat returns to direct `RagService` / legacy RPS path. Exact pre-0.6 behavior when Executive is also OFF.

**Database:** No change required.

---

### Level 3 — Disable Evidence Assembly seam

**When:** Assemble-stage or DFP wrapper regression with Reasoning ON.

```bash
EVIDENCE_ASSEMBLY_ENABLED=false
# restart backend
```

**Effect:** Reasoning ON + EA OFF → Rag passthrough (RPS→DFP inside Rag). Reasoning still owns sufficiency/speech-act **diagnostics** when Reasoning ON.

**Database:** No change required.

---

### Level 4 — Disable Executive seam

**When:** Full return to pre–Knowledge OS chat routing.

```bash
KNOWLEDGE_OS_EXECUTIVE_ENABLED=false
REASONING_SERVICE_ENABLED=false
EVIDENCE_ASSEMBLY_ENABLED=false
REASONING_SPEECH_ACTS_ENABLED=false
# restart backend
```

**Effect:** Identical to Release 0.5 default chat path.

**Database:** No change required.

---

### Level 5 — Code rollback (last resort)

**When:** Defect requires reverting the Release 0.6 commit on disk.

```bash
git revert <release-0.6-closure-commit>   # or checkout prior tag
# redeploy without --clear-db
```

**Rules:**

- **Never** `DROP DATABASE` or `reindex-all` for feature rollback.
- **Never** point runtime at `ai_site_agent_recovery` except under approved incident cutback runbook.
- Preserve `.env` (`DATABASE_URL` → `ai_site_agent`) — deploy rsync excludes `.env`.

## Settings flags (orthogonal)

| Flag | Rollback |
|------|----------|
| `cache_namespace_v2_enabled` | Set `false` in Settings |
| `memory_shadow_write_enabled` | Set `false` in Settings |
| `enable_semantic_diagnostics_v2` | Set `false` in Settings |

These do not affect Release 0.6 speech-act behavior when migration env flags are OFF.

---

## Verification after rollback

```bash
make release-check
curl -s http://127.0.0.1:8000/api/build | jq '.env_flags, .release_status'
```

Expect all migration env flags `false` and legacy chat parity per golden suite.

# RFC-100 Step 046 — Architecture Review: Memory Read Views (Claims by Region)

**Status:** Review & design mapping only — **not approved for implementation**  
**Date:** 2026-07-28  
**Prerequisite:** Release 0.6 engineering accepted; all migration flags OFF  
**Next step after approval:** Implement Step 046 per scope below (no Step 047)

---

## 1. Executive summary

Step 046 introduces the **first read path** from Epistemic Memory toward Reasoning. The frozen architecture (`KNOWLEDGE_OS_ARCHITECTURE_v1.md` §6.2, §7.1) requires Memory to expose **read views** optimized for Reasoning; Reasoning must not query ORM directly.

**Recommendation:** Implement **Option B** — a typed `MemoryRegionRequest` / `MemoryRegionView` facade on top of existing `EpistemicMemoryService` list/get methods. No new tables, no vector index, no HTTP surface, no chat wiring.

**Go recommendation:** **GO** for a bounded read-only facade, with explicit understanding that:

- Production memory today holds **~6 real SI claims** (organization/about scope only) on a handful of sources — not the full 5023-source corpus.
- Step 046 **cannot fix** the Release 0.6 chat diagnostic failures by itself; it only makes Step 047 mechanically possible.
- **No ADR required** if “region” is interpreted as a **caller-scoped filter over existing `scope_json` + provenance**, not a new persisted concept-region entity.

## 2. Chat diagnostics case study (Release 0.6, flags OFF)

**Conversation (legacy path):**

1. «розкажи про банк»
2. «які кредити є?»
3. «а депозити?»

**Reported observations (user-supplied diagnostics):**

- All three turns classified `entity_overview`
- Retrieval candidates included relevant about/history pages; **final sources collapsed to homepage**
- Overview answer emphasized promotions/cards vs stable organizational identity
- Credits answer incomplete; deposits answer falsely “not found” (homepage evidence dominated)
- First-turn latency very high
- Migration flags OFF → **legacy RPS → DFP → Rag** path

### 2.1 Responsibility attribution

| Symptom | Primary owner | Classification |
|---------|---------------|----------------|
| Intent `entity_overview` for bank overview query | **Query Understanding** (`QueryIntentService` + Knowledge Profile) | **SUPPORTED BY CURRENT CODE** — correct for Q1 if profile matches bank |
| «які кредити є?» / «а депозити?» classified `entity_overview` instead of `topic_overview` | **Query Understanding** | **SUPPORTED BY CURRENT CODE** — `match_topic()` should route credits/deposits to `topic_overview` when bank profile is active; misclassification implies wrong profile, pattern order bug, or **diagnostics not showing per-turn intent** |
| Follow-up topic shift not reflected | **Conversation-context interpretation** | **DEFERRED** — QU is per-message; no session topic carry-over in Reasoning/Memory today |
| Candidate pool vs final source collapse to homepage | **Legacy canonical/context finalization** (`CanonicalSourceService`, `context_for_llm`, RPS ranking) | **SUPPORTED BY CURRENT CODE** |
| Overview content = promotions/cards not identity | **Evidence Assembly operational ranking** + **Language** (LLM over weak context) | **SUPPORTED BY CURRENT CODE** — not Memory |
| Incomplete credits enumeration | **QU (enumeration need)** + **retrieval recall** + **sufficiency** (0.6 advisory only when Reasoning OFF) | Mixed |
| Deposits “not found” despite site content | Same + **refusal/fallback** when context is homepage-heavy | Legacy path |
| High first-turn latency | **Retrieval cache miss**, Qdrant, LLM cold start | **DEFERRED** — not Step 046 |

### 2.2 What Memory read views could later assist (Step 047+)

| Need | Could Memory help? | Step 046 prerequisite |
|------|-------------------|------------------------|
| Organization overview | Yes — if claims exist for `page_role=organization_overview` | Read view filtered by scope |
| Product category enumeration | Only after claims extracted for product pages | Claims must exist first (shadow writes + SI coverage) |
| Follow-up topic resolution | Indirect — hints only; **QU still owns need** | Topic filter in `MemoryRegionRequest` |
| Evidence completeness signal | Partial — “claims in region exist / count / support links” | Honest `completeness_unknown` metadata |
| Source authority | **No** — authority is evidential role in Reasoning, not claim count | Must not rank in Memory |

### 2.3 What Memory must NOT solve

- Vector retrieval replacement
- Query intent classification
- Canonical homepage selection
- Conversation coreference (“а депозити?” after credits)
- World-truth verification
- LLM answer generation
- Fixing latency

### 2.4 Would claims-by-region help the case study?

| Scenario | Today | With Step 046 alone | With Step 047 + richer memory |
|----------|-------|---------------------|-------------------------------|
| Bank overview | Retrieval + homepage bias | **Minimal** — only ~6 real claims, all `organization_overview` / `about_page` | Could hint “about” claims if QU asks for entity region |
| Credits enumeration | Misses product pages | **No** — no credit/product claims in memory | Could list claim propositions if SI shadow populated product claims |
| Deposits follow-up | Wrong intent + homepage context | **No** | Same as credits |
| Evidence completeness | RAG sufficiency (when Reasoning ON) | Read view could report `matched_claims=0` honestly | Advisory hint: “memory sparse for topic” |

### 2.5 Failures that remain even with perfect Memory reads

- Wrong per-turn intent without session context
- Homepage canonical collapse in RPS
- LLM hallucination over thin context
- Enumeration completeness without observation-backed product claims
- Latency on cold cache
- Sparse SI shadow coverage (only sources with SI + shadow flag ever written)

|--------|-------|

### 3.4 Indexes (existing)

- `observation_ref`: `source_id`, `chunk_id`, `content_hash`, `observation_key` (unique)

### 3.5 Gaps / risks

| Gap | Impact | Step 046 action |
|-----|--------|-----------------|

| `scope_json` unstructured Text | Filter in Python after SQL prefilter | Accept for v1 bounded reads |
| No `belief_state` table | No derived stance | **DEFERRED** — don't fabricate |
| No concept `region` table | Region = filter, not entity | **PROPOSED MINIMAL INTERPRETATION** |

## 4. Definition of “region” (Step 046)

### 4.1 What region is NOT (frozen architecture)

**REQUIRED BY FROZEN ARCHITECTURE** (`COGNITIVE_ARCHITECTURE.md` §2.3, §7b):

- Not URL path alone
- Not `document_type` taxonomy as ontology
- Not Knowledge Profile taxonomy
- Not industry category
- Not a second retrieval index

Concept regions are **emergent neighborhoods in claim-space** — compressions over claims, revisable when claims merge/split.

### 4.2 Minimal Step 046 interpretation

**PROPOSED MINIMAL INTERPRETATION:**

> **Region** = a **bounded, declarative filter** over the claim store for one **site tenant**, expressed as `MemoryRegionRequest` fields that map to **existing** columns and `scope_json` keys. It is a **read lens**, not a stored object.

V1 region dimensions (all optional except site scope):

| Dimension | Source | Filter mechanism |
|-----------|--------|------------------|
| Site boundary | Deployment corpus (`source_id` set) | `source_ids` allowlist OR join via `observation_ref.source_id` |
| Information need hint | Caller (future Reasoning) | **Not interpreted by Memory** — echoed in response only |
| Topic hint | Caller | Match `scope_json.main_topic` / topic key string if present |
| Page role | `scope_json.page_role` | String equality |
| Document type | `scope_json.document_type` | String equality |
| Language | `scope_json.lang` if ever populated | **DEFERRED** — not reliably present |
| Temporal | `observed_at` on observation | **DEFERRED** — no `as_of` in v1 unless needed |
| Provenance | `provenance_kind`, `attributed_to` | `ProvenanceScope.REAL` default |

**REQUIRES ADR if:** we persist materialized region rows, assign stable region IDs, or let Memory rank claims for answers.

## 7. Recommended design (Option B)

Add to `EpistemicMemoryService` (or thin `MemoryReadViewService` **inside** `epistemic_memory/` package):

- `read_region(request: MemoryRegionRequest) -> MemoryRegionView`
- Internally composes existing `list_claims`, `list_claims_by_source_id`, `list_evidence_links_for_claim`, `get_observation_ref`
- **No new subsystem** — module methods only
- **No chat/Reasoning imports** in Step 046
- **No HTTP** unless explicitly added later (recommend internal-only)

## 8. Proposed typed contracts (not implemented)

```python
@dataclass(frozen=True)
class MemoryRegionRequest:
    # Site scope (at least one required in v1)
    source_ids: tuple[int, ...] | None = None      # allowlist
    source_id: int | None = None                   # single-source shortcut

    # Caller hints (echoed, not interpreted by Memory for ranking)
    information_need: str | None = None            # e.g. "enumeration", "overview"
    topic_key: str | None = None                   # e.g. "credits", "deposits"
    language: str | None = None                    # preference only if scope_json has lang

    # Scope filters (existing scope_json keys)
    page_roles: tuple[str, ...] | None = None
    document_types: tuple[str, ...] | None = None
    proposal_kinds: tuple[str, ...] | None = None

    # Provenance / lifecycle
    provenance_scope: ProvenanceScope = ProvenanceScope.REAL  # default REAL
    active_only: bool = True
    epistemic_statuses: tuple[str, ...] | None = None  # default: all non-superseded

    # Bounds
    limit: int = 50          # clamp 1..MAX_LIMIT
    offset: int = 0
    include_evidence: bool = True
    include_superseded: bool = False
```

```python
@dataclass(frozen=True)
class MemoryClaimView:
    claim_id: int
    proposition: str
    attribution: str                    # attributed_to
    epistemic_status: str
    confidence: float | None
    provenance_kind: str
    provenance_ref: str | None
    scope: dict | None                  # parsed scope_json
    superseded: bool
    revision_of_id: int | None
    evidence: tuple[MemoryEvidenceRef, ...]
    has_support: bool
    has_conflict: bool
    support_observation_source_ids: tuple[int, ...]
```

```python
@dataclass(frozen=True)
class MemoryRegionView:
    request_echo: MemoryRegionRequest
    matched_claims: tuple[MemoryClaimView, ...]
    total_matched: int
    excluded_test_count: int
    excluded_superseded_count: int
    excluded_scope_mismatch_count: int
    provenance_summary: dict[str, int]   # counts by provenance_kind
    limitations: tuple[str, ...]           # e.g. "completeness_unknown"
    completeness_unknown: bool = True    # always true in v1
```

**Not included (explicit):** truth probability, global authority score, independence, contradiction resolution, region coverage certainty.

## 9. Query semantics (deterministic v1)

| Rule | Setting |
|------|---------|
| Active only | `superseded_by_id IS NULL` when `active_only=True` |
| Site scope | Require `source_id` or `source_ids`; reject unbounded global dump |
| Provenance | Default `ProvenanceScope.REAL` (exclude `test` + `attributed_to=fixture`) |
| Test inclusion | Only when `provenance_scope=TEST` or `ALL` (engineering tests) |
| SI inclusion | Included in REAL scope |
| Topic filter | Case-insensitive match on `scope_json.main_topic` or `topic_key` if key present in JSON |
| Page role / doc type | Equality on parsed `scope_json` fields |
| Language | **No filter** unless `scope_json` contains `lang` — **DEFERRED** |
| Ordering | `claim.id ASC` (stable) |
| Limit | Clamp to `MAX_LIMIT` (500) |
| Semantic search | **Forbidden** in Step 046 |
| Grouping | Flat list; optional `group_by_source` in view metadata only |
| Evidence | Include links; claims without evidence still returned with `has_support=false` |

**Return shape:** Deterministic bounded subset with honest exclusion counts — not “all matching” unbounded.

## 10. Authority and truth safety

**REQUIRED BY FROZEN ARCHITECTURE:**

A returned claim is:

- An **attributed proposition** stored by the system
- **Not** automatically true
- **Not** a final answer
- **Not** evidence alone — observation link required for support
- Often `epistemic_status=proposal` (SI shadow)
- **Completeness unknown** for enumeration

Callers distinguish via view fields:

| Question | Field |
|----------|-------|
| Claim exists? | `matched_claims` non-empty |
| Has support? | `has_support` |
| Has conflict evidence? | `has_conflict` |
| Superseded? | `superseded` / excluded by default |
| Proposal only? | `epistemic_status == "proposal"` |
| Test provenance? | Excluded unless explicit scope |

No belief-state semantics in Step 046.

## 11. Step 047 handoff

```
Reasoning (information need)
  → builds MemoryRegionRequest (topic/page_role/source hints)
  → EpistemicMemoryService.read_region()
  → MemoryRegionView (advisory)
  → Reasoning assesses usefulness (not in 046)
  → Evidence Assembly retrieves observations/chunks
  → sufficiency → speech act → Language
```

| Step | Delivers | Consumes |
|------|----------|----------|
| **046** | Read facade + DTOs + unit tests | Existing tables only |
| **047** | `memory_evidence_assist_enabled` wiring | `MemoryRegionView` |

**Step 046 guarantees no chat change:**

- No imports from `chat.py`, `rag_service.py`, `reasoning_service.py`
- No feature flag
- No `memory_version` / `knowledge_version` bump
- Golden suite unchanged

**Duplicate retrieval avoidance (047):** Memory hints choose **which sources/claims to prioritize**; Evidence Assembly still performs **one** sensory retrieval execution — Memory does not call Qdrant.

**Claims in prompts:** Step 047 must not inject claim text as answer without linked observation content in evidence bundle.

## 13. Security and site isolation

| Rule | Implementation |
|------|----------------|
| Exclude test provenance by default | `ProvenanceScope.REAL` |
| Internal-only API | Package-level service; no new public route |
| No unrestricted dumps | Require site `source_id(s)` + limit |
| Single-site deployment today | Full corpus is one tenant; `source_ids` filter prevents accidental cross-source leakage in tests |
| DTOs only | Continue `ClaimView` pattern |
| Pagination | `limit`/`offset` + total counts |

Multi-site future: region request must include tenant/site key — **DEFERRED** (no schema yet).

# 1. Purpose

Convert Master Program packages into:

1. **Waves** — dependency-safe groups with shared objectives  
2. **Steps** — end-to-end implementation slices (minimize review overhead)  
3. **Critical path** — minimum paths to usable product and full completion  
4. **Milestones** — objective completion states  
5. **First Step recommendation** — exact starting implementation Step  

---

# 2. Ordering principles

1. Respect every **hard** dependency from the Master Program.  
2. Maximize **parallel** work only where Master Program §4.3 allows.  
3. Prefer **logical end-to-end slices** over tiny technical commits.  
4. Obey Execution Strategy: move once, no duplicate owners at Step DoD, Eng isolation before deleting eng chrome, Home empty only after receivers exist.  
5. **G11** remains excluded from Dashboard completion path (boundary only).  
6. **G10** is optional parallel to UI; never blocks UI Steps.  
7. Gate templates (**G9-P1**) land before user-facing Gate claims.  
8. Continuous **G8-P2** (migrate-on-touch) is embedded inside surface Steps—not a separate late rewrite.

```
S001 (routes + Eng Mode + General)
  → (S002 ∥ S003 ∥ S004 ∥ S005)
  → S006 (isolate eng from Ask/Settings/Knowledge)
```

`S001 → S005 → S003 → S006 → S007`  
(Ask + Activity + isolation + Home default), with S002/S004 still required for full Dashboard Complete but not for a thin “Ask+Home” usable slice.

# 8. Final execution recommendation

## First implementation Step: **S001**

**S001 — Bootstrap + IA substrate + Engineering Mode unlock**

### Why this first

1. **Hard-dependency root:** Almost all move packages require `G1-P1` and Eng scaffolds (`G2-P3`). Starting elsewhere forces temporary homes (forbidden by Execution Strategy R6) or deletes eng chrome (forbidden).  
2. **Largest unlock:** One Step unblocks parallel S002–S005 and enables lawful S006 isolation.  
3. **Risk control:** Establishes Mode isolation *before* product cutovers claim “simplified” surfaces; avoids painting legacy into new names without Eng receivers.  
4. **Process readiness:** Gate template (G9-P1) and SoT clarity (G12) exist before user-facing Gates on S002+.  
5. **Structure readiness:** `G8-P1` skeleton makes migrate-on-touch mechanical for later Steps.  
6. **Review efficiency:** One XL end-to-end unlock beats many tiny PRs that cannot accept independently.

### What S001 must not do

- Full Knowledge/Insights/Settings/Ask/Home migrations (those are S002–S007)  
- Strip diagnostics/SI/Advanced without receivers  
- Touch RFC-100 / Step 067 / ops gates  
- Implement G11 backend deferred work  

### Immediate next after S001

Start **S002 ∥ S003 ∥ S004 ∥ S005** in parallel, then **S006 → S007 → S008**.

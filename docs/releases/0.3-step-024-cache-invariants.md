# RFC-100 Step 024 — Cache Namespace v2 invariant validation

**Release track:** 0.3  
**Type:** Tests and documentation only — no production behavior change.

## Purpose

Prove that cache invalidation after a `memory_version` bump is driven entirely by namespace evolution, and that cache services remain unaware of Epistemic Memory.

## Invariants validated

See [MEMORY_VERSION.md](../MEMORY_VERSION.md#cache-namespace-invariants-step-024).

## Test file

`backend/tests/test_cache_namespace_v2_invariants.py`

Covers:

- Flag OFF / ON namespace behavior
- Cross-version isolation (`memory_version` ↔ `knowledge_version`)
- Deterministic namespace and cache keys
- Property tests over version/setting combinations
- Static negative tests (no `bump()` in cache modules, no direct `settings.memory_version` reads outside allowlist)

## Run

```bash
cd backend
.venv/bin/pytest tests/test_cache_namespace_v2_invariants.py tests/test_cache_namespace_v2.py -m unit -q
```

## Explicit non-goals (Step 024)

- Claim invalidation
- Epistemic Memory tables or writes
- Automatic memory bumps
- Cache algorithm changes

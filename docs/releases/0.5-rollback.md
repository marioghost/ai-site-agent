## Deployment procedure

### 1. Database migration

No new migrations for Release 0.5.

```bash
cd backend
.venv/bin/alembic upgrade head
# Expected: 0015_memory_shadow_write_enabled (head)
```

### 2. Build & test

```bash
make release-check

cd backend
.venv/bin/pytest \
  tests/test_tension_surfacing_service.py \
  tests/test_tension_acceptance.py \
  tests/test_understanding_tensions_api.py \
  tests/test_operational_metrics.py \
  -m unit -q
```

### 3. Deploy application

Deploy backend + dashboard as usual.

### 4. Post-deploy smoke

- Health / build OK
- `GET /api/metrics` includes `kos_open_tensions`, `kos_support_deficit_tensions`, `kos_conflict_tensions`
- `GET /api/metrics/operational` includes tension fields + `tension_claim_scan_limit`
- Admin: `/understanding` loads (hypothesis banner visible)
- Non-admin cannot access Understanding route
- Chat smoke unchanged vs Release 0.4

---

## Rollback

Release 0.5 adds **no schema**. Rollback is **redeploy prior application build**.

1. Redeploy last Release 0.4 (or prior) backend + dashboard artifacts.
2. Restart backend / reload nginx.
3. Confirm `/api/metrics` no longer requires tension fields for smoke (0.4 may lack them — OK).
4. Confirm chat smoke green.

**Do not** run Alembic downgrade for 0.5 (nothing to downgrade).

If operators misread tension gauges as confirmed errors: clarify using [TENSION_SURFACING.md](../TENSION_SURFACING.md) — hypotheses only; no maintenance running.

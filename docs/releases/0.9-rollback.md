# Release 0.9 — Rollback procedures

**RFC-100 Release 0.9** (Steps 058–062 + Index→Integrate)  
**Default runtime intent:** `MAINTENANCE_EXECUTION_ENABLED` **OFF**; investigation budget fail-closed; Memory assist/shadow **OFF**

**Public operator entry point:** `bash deploy/manage_deploy.sh <command>`  
Syntax source of truth: `bash deploy/manage_deploy.sh help`

Prefer least-disruptive rollback first. **Do not** use `ai_site_agent_recovery` as a feature rollback target. **Do not** clear Qdrant. **Do not** reindex merely to roll back 0.9 behaviour. **Do not** use emergency deploy overrides for routine Release 0.9 rollback.

Release 0.9 engineering adds **no answer-influencing path** when maintenance execution is OFF. Rollback is normally **env- or code-level** only.

---

## Level 1 — Keep / force maintenance execution OFF (preferred)

### Disable maintenance execution

```text
MAINTENANCE_EXECUTION_ENABLED=false
# optional explicit budget hard-stop:
MAINTENANCE_INVESTIGATIONS_PER_CYCLE=0
# restart backend if env was previously enabled
```

**When:** Any maintenance/investigation regression is suspected, or an approved staging experiment ends.  
**Effect:** Step 059 skips execution (flag_off / budget_zero). Steps 058 ranking and 061 observation remain inert for live work when no cycle runs.  
**Database:** No change required. No schema rollback.

### Confirm operator identity (no redeploy required for env-only)

```bash
bash deploy/manage_deploy.sh status
bash deploy/manage_deploy.sh build-info
bash deploy/manage_deploy.sh health
```

---

## Level 2 — Code rollback (known-good `origin/main`)

`deploy/manage_deploy.sh` **does not** accept an arbitrary prior commit as a deploy argument. Release deploy always builds a **clean worktree from `origin/main`**.

Therefore Level 2 means: put the **known-good commit on `origin/main`**, then run the canonical deploy chain.

### 1. Exact rollback target

Choose one accepted tip, for example:

| Target class | Example tip (fill at execution) |
|--------------|----------------------------------|
| Last Release **0.8** accepted tip (pre-058) | record full SHA before 0.9 cutover |
| Last known-good interim 0.9 tip before the regressing change | record full SHA |

Preferred git path: an approved **revert merge** (or equivalent) so `origin/main` advances to restore prior behaviour **without** force-push. Do **not** deploy from feature branches, dirty trees, or local-only commits.

### 2. Backup / status check

```bash
bash deploy/manage_deploy.sh status
bash deploy/manage_deploy.sh backup db
```

Confirm: local `main` == `origin/main` == **rollback target SHA**; working tree **clean**.

### 3. Canonical deploy

```bash
sudo bash deploy/manage_deploy.sh deploy full
bash deploy/manage_deploy.sh health
bash deploy/manage_deploy.sh build-info
bash deploy/manage_deploy.sh smoke
bash deploy/manage_deploy.sh verify-release
```

---

## Explicit non-rollback actions

- Do **not** delete Epistemic Memory rows to “undo” 0.9.
- Do **not** clear Qdrant or force reindex for feature rollback.
- Do **not** introduce `kos_tension_resolved_total` or tension-closure work as a rollback path.
- Do **not** reopen frozen Engineering Packages for Steps 058–061 or Index→Integrate as part of rollback.
- Step **062** engineering closure itself rolls back by reverting the closure commit(s) (docs + build metadata).

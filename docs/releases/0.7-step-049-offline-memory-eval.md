## Summary

Step 049 adds an **offline** evaluation package that aggregates frozen Memory Assist (047) and Canonical Shadow (048) diagnostics into:

1. Versioned JSON report (`schema_version=1`)
2. Human Markdown report
3. Explicit recommendation: `NO_GO` | `CONDITIONAL` | `STAGING_CANDIDATE`

Recommendations apply **only** to controlled staging consideration. They never authorize production enablement, default-ON flags, answer-quality claims, or Memory/canonical “correctness.”

## Ownership

| Owns | Must never own |
|------|----------------|
| `app/services/evaluation/*` | Chat, Rag, Reasoning runtime, Retrieval, EA, Language, Memory |
| CLI `scripts/run_memory_assist_eval.py` | Feature flags, migrations, DB writes |
| Synthetic fixtures + reports | Live harvest (future, separate) |

**No Step 049 feature flag exists.**

## Inputs

- `EvalTurnRecord` — `assist_diagnostics` / `shadow_diagnostics` (serialized `to_diagnostics()` or DTO adapters)
- Optional `CorpusEvalSnapshot` (caller-supplied counters; aggregator does **not** query DB)
- Versioned `MemoryAssistEvalThresholdsV1` (engineering gates, not empirical truth)

Forbidden in reports: query text, answers, prompts, claim propositions, chunk text, unrestricted URLs.


## Threshold semantics

Thresholds are **operational engineering gates**. Markdown reports state:

> These thresholds are operational engineering gates, not measures of knowledge accuracy.

## Forbidden metrics

Do not invent or report:

- accuracy / correctness percentages
- Memory quality score
- answer improvement score
- canonical “winner”
- LLM-as-judge scores

## Recommendation meanings

| Code | Meaning |
|------|---------|
| `NO_GO` | Assist must remain OFF in staging and production |
| `CONDITIONAL` | Default OFF; limited staging experiment needs explicit approval + conditions |
| `STAGING_CANDIDATE` | Supports controlled staging experiment only — **not** production / default ON |

## Live corpus expectation

Current sparse Memory coverage is expected to yield **`NO_GO`** on real staging harvests until the coverage gate improves. Synthetic `STAGING_CANDIDATE` fixtures exist only to validate recommendation rules.

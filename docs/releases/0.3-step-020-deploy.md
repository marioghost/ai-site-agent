# RFC-100 Step 020 — Deploy note: `memory_version`

**Release track:** 0.3 (substrate only; no runtime behavior change)

## What changed

- Additive column `settings.memory_version` (integer, `NOT NULL`, server default `1`).
- Alembic revision: `0012_memory_version` (after `0011_semantic_diagnostics_v2`).

## Deploy requirement

**Before or during deploy**, run migrations on the target database:

```bash
cd backend
.venv/bin/alembic upgrade head
```

Verify revision:

```bash
.venv/bin/alembic current
# Expected: 0012_memory_version (head)
```

## Rollback

Downgrade only if rolling back Step 020 specifically:

```bash
.venv/bin/alembic downgrade 0011_semantic_diagnostics_v2
```

Dropping `memory_version` is safe while cache namespace v2 is not enabled (Steps 023+).

## Runtime impact

| Area | Impact |
|------|--------|
| Chat | None |
| Retrieval / answer cache | None (`knowledge_version` unchanged) |
| `memory_version` bumps | Via `MemoryVersionService` only (Step 021); no automatic bumps yet |
| Dashboard | None required |

## Feature flags

No new flags in Step 020. Ship with existing 0.2 flag defaults (`KNOWLEDGE_OS_EXECUTIVE_ENABLED=false`, `enable_semantic_diagnostics_v2=false`).

## Deployment procedure

### 1. Database migration

```bash
cd backend
alembic upgrade head
```

Adds `settings.enable_semantic_diagnostics_v2` (default `false`). No other schema changes in 0.2.

### 2. Build & test

```bash
cd backend
.venv/bin/pytest tests/test_golden_chat_parity.py tests/test_golden_queries_schema.py \
  tests/test_semantic_diagnostics_schema.py tests/test_knowledge_profile_preset_deprecation.py \
  -v -m unit

cd ../dashboard
npm test && npx tsc --noEmit
```

### 3. Deploy application

Deploy backend + dashboard as usual.

**Environment (production first deploy — keep defaults):**

```bash
KNOWLEDGE_OS_EXECUTIVE_ENABLED=false
```

**Settings (via dashboard or DB):**

- `enable_semantic_diagnostics_v2` = **false** (default after migration)

### 4. Post-deploy smoke (flags OFF)

- Health: `GET /api/health` → 200
- Chat test: normal response; `understanding_trace` absent unless debug + flag ON
- Knowledge Profile page: legacy banner visible (informational only)
- `POST /api/knowledge-profile/presets/load` → 200; response includes `Deprecation: true` header (body unchanged)

## Rollback procedure

### Level 1 — Disable flags (no redeploy)

| Flag | Action |
|------|--------|
| `enable_semantic_diagnostics_v2` | Set false in Settings — immediate, no restart |
| `KNOWLEDGE_OS_EXECUTIVE_ENABLED` | Set `false` or unset → restart backend |

### Level 2 — Revert application deploy

1. Deploy previous backend + dashboard artifacts (0.1 or last known good)
2. **Do not** downgrade Alembic unless necessary — column `enable_semantic_diagnostics_v2` is additive and ignored by 0.1 code
3. Clear retrieval/answer caches if diagnostics or routing changed during testing
4. Verify golden smoke (10-query 0.1 suite if rolled back to 0.1 artifact only)

### Level 3 — Database downgrade (rare)

Only if migration `0011` must be removed:

```bash
cd backend
alembic downgrade 0010_document_first_retrieval
```

**Warning:** Only safe if no code depends on the column. Release 0.2 code tolerates missing column via `getattr(..., False)` in settings API read path, but ORM model expects column after 0.2 deploy.

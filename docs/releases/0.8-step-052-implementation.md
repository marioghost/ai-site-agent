# RFC-100 Step 052 — Implementation note (Option A)

**Status:** implemented on `feat/step-052-settings-api-boost-removal` (pending review)  
**Architecture:** `docs/releases/0.8-step-052-architecture-review.md`

## Scope delivered

Removed from Settings API contract (`SettingsRead` / `SettingsUpdate` / `_to_read` / `update_settings`):

- `title_match_boost`
- `heading_match_boost`
- `homepage_boost_enabled`
- `homepage_boost_value`
- `short_query_lexical_boost`

## Explicitly unchanged

- ORM columns on `settings`
- `DocumentScorer` title/heading reads
- `RetrievalPipelineService` homepage inject reads
- `cache_namespace_service` hash inputs
- No Alembic migration
- No dashboard changes (Step 053)
- No KP / Reasoning / Evidence Assembly changes

## Compatibility

`SettingsUpdate` retains `extra="ignore"`, so legacy PUT bodies that still send the five fields are accepted and do not write ORM boost columns.

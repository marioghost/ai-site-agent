# Release 0.7 — Step 046: Memory read views (claims by region)

**RFC-100 Step 046**  
**Lifecycle state:** Implemented — contract hardened

## Summary

Adds an **internal, read-only** typed facade:

```
MemoryRegionRequest → EpistemicMemoryService.read_region() → MemoryRegionView
```

Region is a **bounded filter lens** over existing claims — not a persisted entity, taxonomy, or ranking engine.

**No chat behavior change.** No feature flag. No HTTP route.

## Region definition

Requires positive `source_id` or `source_ids` (validated before SQL). Optional filters on parsed `scope_json` keys (`page_role`, `document_type`, `proposal_kind`, `main_topic`), provenance scope, active/superseded lifecycle, and bounded pagination.

Source isolation uses **linked observations** (`evidence_link → observation_ref.source_id`), not `scope_json.source_id` alone.

## Evidence semantics (`MemoryClaimView`)

| Field | `include_evidence=True` | `include_evidence=False` |
|-------|-------------------------|--------------------------|
| `evidence_loaded` | `true` | `false` |
| `evidence` | loaded refs | `()` |
| `has_support` | `true` / `false` | `null` — **not interpretable** |
| `has_conflict` | `true` / `false` | `null` — **not interpretable** |

Region-level `evidence_not_requested` limitation is also set when evidence was not loaded.

**Step 047 obligation:** check `evidence_loaded` (or `evidence_not_requested` in limitations) before interpreting support/conflict booleans.

## Lifecycle truth table

| `active_only` | `include_superseded` | Result |
|---------------|----------------------|--------|
| `true` | `false` | Active claims only (superseded excluded) |
| `true` | `true` | All claims including superseded |
| `false` | `true` | All claims including superseded |
| `false` | `false` | **`ValueError`** — ambiguous; rejected before SQL |

## Count / diagnostic semantics

| Field | Meaning |
|-------|---------|
| `total_matched` | Full filtered count **before** pagination |
| `provenance_excluded_count` | Claims excluded by provenance scope filter (REAL/TEST/ALL) |
| `excluded_test_count` | Deprecated alias of `provenance_excluded_count` |
| `excluded_superseded_count` | Superseded claims excluded when lifecycle is active-only |
| `excluded_scope_mismatch_count` | Status / scope_json / topic filters |
| `provenance_summary` | Provenance kinds over **all** matched claims (pre-pagination) |
| `page_provenance_summary` | Provenance kinds on the current page only |

Exclusion counters are **diagnostic** and **not additive** — one claim increments at most one counter per filter stage.

## DTO immutability

`scope` and `provenance_summary` use shallow `MappingProxyType` copies. Top-level mutation raises `TypeError`. Nested dict/list values inside `scope_json` are not deep-frozen.

## Truth safety

- Claims are attributed propositions — not automatic truth
- `completeness_unknown` is always `true`
- Limitation codes are stable strings (`sparse_memory`, `no_matching_claims`, …)
- No authority scores, belief states, or contradiction resolution

## Sparse real memory

Production shadow data remains small (~6 real SI claims, organization/about scope). Empty or sparse regions are expected and reported honestly.

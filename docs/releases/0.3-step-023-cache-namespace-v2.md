# RFC-100 Step 023 — Deploy note: `cache_namespace_v2_enabled`

**Release track:** 0.3  
**Default:** OFF (no production cache behavior change)

## What changed

- Additive column `settings.cache_namespace_v2_enabled` (boolean, `NOT NULL`, server default `false`).
- Alembic revision: `0013_cache_namespace_v2_enabled` (after `0012_memory_version`).
- When flag ON, cache namespace includes `memory_version` from `MemoryVersionService`.

## Deploy requirement

```bash
cd backend
.venv/bin/alembic upgrade head
```

Verify:

```bash
.venv/bin/alembic current
# Expected: 0013_cache_namespace_v2_enabled (head)
```

## Enabling in staging

1. Confirm migration applied.
2. Set `cache_namespace_v2_enabled=true` in Settings (API or DB).
3. Optional: bump memory via `POST /api/settings/memory-version/bump` and confirm cache miss behavior.
4. Keep **OFF** in production until Release 0.3 acceptance.

## Rollback

```bash
.venv/bin/alembic downgrade 0012_memory_version
```

Or leave column in place and set flag `false` — safe, restores legacy namespace behavior immediately.

See [FEATURE_FLAGS.md](../FEATURE_FLAGS.md) and [MEMORY_VERSION.md](../MEMORY_VERSION.md).

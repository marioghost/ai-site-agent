# 4. Proven root cause

## 4.1 Primary root cause (frozen composite)

**LOCKED DECISION — primary remediation target (H1 + H2 + H3):**

1. Request DB session survives the **entire LLM / model-wait lifetime** (non-stream).  
2. Stream DB session survives the **entire SSE stream lifetime** (request-scoped `get_db` bound to `StreamingResponse`).  
3. Cancellation cleanup is **delayed by sync streaming** (blocking Ollama between yields; GeneratorExit only at next yield).  
4. **DB acquisition / first SQL occurs before chat admission** (`chat_slot`).

## 4.2 Epistemic classes

| Statement | Class |
|-----------|--------|
| `get_db` yields session closed in `finally` | **PROVEN** (`database.py`) |
| Non-stream: settings/session SQL then `chat_slot` then Executive/LLM on same `db` | **PROVEN** (`chat.py`) |
| Stream: `db` used before `StreamingResponse`; generator uses same `db` through stream | **PROVEN** (`chat.py`) |
| Pool config 10 / overflow 20 / timeout 30 on `/opt` | **PROVEN** (`AppConfig` + `/opt/.env`) |
| Single uvicorn worker | **PROVEN** (systemd unit) |
| Sustained ~93.5% 5xx; progressive collapse vs warmup | **PROVEN** (durable Step 066 results) |
| Journal QueuePool timeout during load | **EVIDENCE-SUPPORTED** (ops journal; not duplicated in git JSON) |
| Cancelled client streams leave server-side “zombie” holders until sync Ollama returns | **EVIDENCE-SUPPORTED** (architecture + progressive FAIL + cancel schedule) |
| Background workers are the primary starvation source | **HYPOTHESIS** (low–med; not primary) |
| True leak where `close()` never runs | **HYPOTHESIS** (medium; `finally` exists) |
| Pool too small as primary cause at client concurrency ≤2 | **HYPOTHESIS rejected as primary** |

Do **not** upgrade **HYPOTHESIS** to fact in implementation reports without new proof.

# 5. Session ownership contract

**LOCKED DECISION — future model:**

### 5.1 Non-stream Ask

| Phase | DB session |
|-------|------------|
| Chat admission (`chat_slot`) | **May** exist only if no pool checkout yet; prefer admission **before** first checkout (§6) |
| Settings read / session resolve / user message persist | **Short-lived** session allowed; **must close** before LLM wait |
| LLM / embedding / Reasoning generation wait | **Must not** hold a checked-out Ask session |
| Assistant message / diagnostics persist | **New** short-lived session allowed; **must close** before response return |
| After response | **No** Ask session open |

### 5.2 Streaming Ask

| Phase | DB session |
|-------|------------|
| Pre-stream setup (settings, session, user message) | Short-lived; **must close before** entering generation / token loop |
| SSE body / Ollama `chat_stream` / token yields | **Must not** hold request `get_db` session across the stream |
| Final assistant persist | New short-lived session after generation completes (or best-effort on orderly end) |
| Client disconnect / cancel | Cleanup **must** release chat_slot; must not depend on finishing full LLM to release DB (DB already released pre-generation) |
| Dependency `get_db` on route | Must not imply stream-scoped connection for full SSE lifetime after remediation |

### 5.3 Persistence / history

- History writes remain required for product parity.  
- Writes use **operation-scoped** sessions, not one session spanning LLM.  
- Duplicate-write risk must be tested (idempotent request_id / single final persist).

### 5.4 Settings reads

- Allowed in short-lived sessions at request start.  
- Must not keep connection open across model waits.

### 5.5 Health / metrics / build

- May use `get_db` / same pool (**no second pool** without Architecture Review revision).  
- Must not be “fixed” solely by enlarging pool.  
- Optional fail-soft around pool acquire **only after** Ask lifetime fix; must not falsely report DB healthy when unprobeable.

### 5.6 Background workers

- Retain own `SessionLocal` / `worker_session` pattern.  
- Remain shared-pool consumers; not redesigned in this step.  
- Must not be used as excuse to skip Ask lifetime remediation.

# 6. Admission ordering

**LOCKED DECISION — canonical order (Ask):**

```text
1. HTTP accept / auth (unchanged)
2. Chat admission (concurrency.chat_slot)     ← BEFORE pool checkout / first SQL when feasible
3. Short DB session: settings + session + user message → close
4. LLM slot (inside generation path as today)
5. Reasoning / Evidence / Rag / stream generation   ← NO Ask DB session held
6. Short DB session: assistant persist / diagnostics → close
7. Response complete / SSE end
8. Cleanup: slots released; no orphan sessions
```

**LOCKED DECISION — DB checkout before admission:**

- **Not permitted** as the steady-state design after remediation.  
- Pre-remediation code that checks out before `chat_slot` is the defect class H3.  
- If a minimal transitional read is unavoidable, it must not hold the connection across admission wait or LLM.

# Release 0.7 — Rollback procedures

**RFC-100 Release 0.7** (Steps 046–050)  
**Default runtime:** Release 0.7 Settings flags **OFF**; migration env flags **OFF** (legacy behavior)

Release 0.7 introduces **no answer-influencing Memory path** when flags are OFF. Rollback is normally **flag- or code-level** only. **Do not** use `ai_site_agent_recovery` as a feature rollback — that database is incident infrastructure only.

**Preferred rollback:** disable flags. No Memory row deletion, no reindex, and no Qdrant clear are required for feature rollback.

---

## Rollback levels (least → most disruptive)

### Level 1 — Disable Memory Canonical Shadow

**When:** Shadow diagnostics are noisy or a shadow-path regression is suspected.

```bash
# Settings API / dashboard / SQL — set:
memory_canonical_shadow_enabled = false
# restart not required for Settings flags
```

**Effect:** Assist (if ON) continues; shadow comparison stops. Answers unchanged either way (shadow is diagnostic-only).

**Database:** No change required.

---

### Level 2 — Disable Memory evidence assist

**When:** Assist path regression, unexpected Memory reads, or staging experiment ends.

```bash
memory_evidence_assist_enabled = false
memory_canonical_shadow_enabled = false   # shadow requires assist; disable explicitly
```

**Effect:** Zero Memory reads on the chat path. Shadow cannot be effective.

**Database:** No change required. Existing Memory rows remain untouched.

---

### Level 3 — Disable cache namespace v2 (if needed)

**When:** Cache identity / invalidation issues tied to Memory version segments.

```bash
cache_namespace_v2_enabled = false
memory_evidence_assist_enabled = false
memory_canonical_shadow_enabled = false
```

**Effect:** Assist/shadow cannot be effective (prerequisites). Retrieval/answer caches return to pre–namespace-v2 identity rules.

**Database:** No change required. Optional cache clear is operational, not schema rollback.

---

### Level 4 — Disable Reasoning seam

**When:** Any Reasoning-path regression (including assist coordination).

```bash
REASONING_SERVICE_ENABLED=false
REASONING_SPEECH_ACTS_ENABLED=false   # redundant but explicit
# restart backend
```

Also keep Settings assist/shadow **false**.

**Effect:** Chat returns to direct `RagService` / legacy RPS path (subject to Executive flag).

**Database:** No change required.

---

### Level 5 — Disable Evidence Assembly seam

**When:** Assemble-stage regression with Reasoning ON.

```bash
EVIDENCE_ASSEMBLY_ENABLED=false
# restart backend
```

**Effect:** Reasoning ON + EA OFF → Rag passthrough assemble path. Assist still requires Reasoning ON and its Settings flags.

**Database:** No change required.

---

### Level 6 — Disable Executive seam

**When:** Full return to pre–Knowledge OS chat routing.

```bash
KNOWLEDGE_OS_EXECUTIVE_ENABLED=false
REASONING_SERVICE_ENABLED=false
EVIDENCE_ASSEMBLY_ENABLED=false
REASONING_SPEECH_ACTS_ENABLED=false
# restart backend
```

Keep Release 0.7 Settings flags **false**.

**Effect:** Identical to Release 0.5/0.6 default chat path with all migration env flags OFF.

**Database:** No change required.

---

### Level 7 — Application code rollback

**When:** Defect requires reverting Release 0.7 commits on disk.

```bash
git revert <release-0.7-closure-commit>   # or redeploy prior accepted revision
# redeploy without --clear-db
```

**Rules:**

- **Never** `DROP DATABASE`, `reindex-all`, or clear Qdrant for feature rollback.
- **Never** point runtime at `ai_site_agent_recovery` except under an approved incident cutback runbook.
- Preserve `.env` (`DATABASE_URL` → `ai_site_agent`) — deploy rsync excludes `.env`.

---

### Level 8 — Schema downgrade (last resort, explicit only)

**When:** Operators explicitly require removing Settings columns introduced by 0016/0017.

```bash
cd backend
# ONLY on a disposable or explicitly approved target — NEVER casually on production
.venv/bin/alembic downgrade 0015_memory_shadow_write_enabled
```

**Clarify:**

- Prefer leaving columns in place with flags **false**.
- Downgrade removes only the additive boolean columns (no data rewrite of Memory tables).
- Do **not** delete Epistemic Memory rows as part of Release 0.7 rollback.
- Do **not** apply downgrades during engineering closure validation.

---

## What rollback does **not** require

| Action | Required for 0.7 feature rollback? |
|--------|-------------------------------------|
| Delete Memory claims / observations / evidence | **No** |
| Reindex corpus | **No** |
| Clear or rebuild Qdrant | **No** |
| Switch to `ai_site_agent_recovery` | **No** |
| Clean Epistemic Memory test rows | **No** (orthogonal ops task) |

---

## Verification after rollback

```bash
make release-check
curl -s http://127.0.0.1:8000/api/build | jq '.settings_flags, .env_flags, .release_status'
```

Expect:

- `memory_evidence_assist_enabled` / `memory_canonical_shadow_enabled` → `false`
- `effective` for assist/shadow → `false`
- Golden / smoke chat parity with flags OFF

---

## Incident database note

`ai_site_agent_recovery` is **not** a rollback target for Release 0.7 feature flags. It exists only as temporary infrastructure from prior database incidents.

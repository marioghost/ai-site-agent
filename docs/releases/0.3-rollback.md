## Deployment procedure

### 1. Database migration

```bash
cd backend
.venv/bin/alembic upgrade head
```

Expected head: `0013_cache_namespace_v2_enabled`

Adds:

- `settings.memory_version` (integer, NOT NULL, default `1`)
- `settings.cache_namespace_v2_enabled` (boolean, NOT NULL, default `false`)

### 2. Build & test

```bash
cd backend
.venv/bin/pytest \
  tests/test_memory_version_schema.py \
  tests/test_memory_version_service.py \
  tests/test_memory_version_bump_api.py \
  tests/test_cache_namespace_v2.py \
  tests/test_cache_namespace_v2_invariants.py \
  tests/test_operational_metrics.py \
  tests/test_golden_chat_parity.py \
  -m unit -q
```

### 3. Deploy application

Deploy backend as usual. Dashboard unchanged for 0.3.

**Environment (production — keep defaults):**

```bash
KNOWLEDGE_OS_EXECUTIVE_ENABLED=false
```

**Settings (via dashboard or DB):**

- `enable_semantic_diagnostics_v2` = **false**
- `cache_namespace_v2_enabled` = **false**

### 4. Post-deploy smoke (flags OFF)

- Health: `GET /api/health` → 200
- Metrics: `GET /api/metrics` → contains `kos_memory_version 1` (or current value)
- Metrics JSON: `GET /api/metrics/operational` → `{ "memory_version": 1, "knowledge_version": N }`
- Chat: smoke query behaves as before Release 0.3
- Golden unit suite green

### 5. Optional staging validation (before enabling cache v2)

1. Set `cache_namespace_v2_enabled=true` on staging only.
2. Populate retrieval/answer cache with a query.
3. `POST /api/settings/memory-version/bump` (admin token).
4. Re-run same query → expect cache miss (namespace hash changed).
5. Confirm `kos_memory_version` incremented on `/api/metrics`.

## Rollback

### Fast rollback (recommended)

**No code revert required** for behavior rollback:

| Action | Effect |
|--------|--------|
| Set `cache_namespace_v2_enabled=false` | Immediate — legacy cache namespace |
| Keep using app with new columns | Columns ignored when flag OFF |

Production chat and cache behavior match Release 0.2.

### Disable manual bump exposure

No flag — endpoint exists but is admin-only and inert for cache when `cache_namespace_v2_enabled=false`. Restrict admin tokens if needed.

### Alembic downgrade (only if required)

Rollback Step 023 only:

```bash
cd backend
.venv/bin/alembic downgrade 0012_memory_version
```

Rollback Step 020–023:

```bash
.venv/bin/alembic downgrade 0011_semantic_diagnostics_v2
```

**Warning:** Downgrade drops `memory_version` and `cache_namespace_v2_enabled` columns. Safe only if no downstream dependency on stored memory revision history.

### Full artifact rollback

Deploy previous backend artifact (Release 0.2). Migrations `0012`/`0013` columns remain in DB but are unused by 0.2 code — harmless.

## Kill-switch summary

| Concern | Action |
|---------|--------|
| Cache v2 causing unexpected misses | `cache_namespace_v2_enabled=false` in Settings |
| Operator bump mistakes | Restrict admin API access; version is monotonic only |
| Metrics noise | Do not scrape `/api/metrics`; no runtime impact |

## Deployment procedure

### 1. Database migration

```bash
cd backend
.venv/bin/alembic upgrade head
```

Expected head: `0015_memory_shadow_write_enabled`

Adds since Release 0.3:

| Migration | Adds |
|-----------|------|
| `0014_epistemic_memory_tables` | `observation_ref`, `claim`, `evidence_link` |
| `0015_memory_shadow_write_enabled` | `settings.memory_shadow_write_enabled` (default `false`) |

### 2. Build & test

```bash
cd backend
.venv/bin/pytest \
  tests/test_epistemic_memory_schema.py \
  tests/test_epistemic_memory_service.py \
  tests/test_claim_extraction_from_si.py \
  tests/test_epistemic_memory_shadow_write.py \
  tests/test_epistemic_shadow_memory_version_bump.py \
  tests/test_epistemic_memory_roundtrip.py \
  tests/test_golden_chat_parity.py \
  -m unit -q
```

### 3. Deploy application

Deploy backend as usual. Dashboard unchanged for 0.4.

**Environment (production — keep defaults):**

```bash
KNOWLEDGE_OS_EXECUTIVE_ENABLED=false
```

**Settings (via dashboard or DB):**

- `enable_semantic_diagnostics_v2` = **false**
- `cache_namespace_v2_enabled` = **false**
- **`memory_shadow_write_enabled` = **false****

### 4. Post-deploy smoke (flags OFF)

- Health: `GET /api/health` → 200; `migration_version` includes `0015`
- Build: `GET /api/build` → `feature_flags.memory_shadow_write_enabled` is `false`
- Metrics: `GET /api/metrics` → `kos_memory_version` present
- Chat: smoke query behaves as before Release 0.4
- Golden unit suite green
- Epistemic tables exist but remain **empty** until shadow flag ON

### 5. Optional staging validation (before enabling shadow writes)

1. Set `memory_shadow_write_enabled=true` on **staging only**.
2. Run Source Intelligence generation (batch or inline indexing).
3. Verify idempotency: re-run SI → no duplicate observations (`obs:source:{id}:si`).
4. Verify `memory_version` bumps only on first persist per new rows.
5. Verify chat/retrieval golden suite still green with flag ON (shadow does not consume memory).
6. Optionally enable `cache_namespace_v2_enabled=true` and confirm bump invalidates namespace.

See [FEATURE_FLAGS.md](../FEATURE_FLAGS.md#memory_shadow_write_enabled) and [ADR-0001](../adr/0001-shadow-observation-key-per-source.md).

## Rollback

### Fast rollback (recommended)

**No code revert required** for behavior rollback:

| Action | Effect |
|--------|--------|
| Set `memory_shadow_write_enabled=false` | Immediate — zero epistemic writes and auto-bumps |
| Keep prior flags OFF | Chat, retrieval, cache unchanged from Release 0.3 |

Existing epistemic rows (if any were written during staging) remain in DB but are **not read** by chat or retrieval.

### Disable shadow writes only

Set `memory_shadow_write_enabled=false`. No restart required. SI and indexing continue unchanged; no new epistemic rows.

### Alembic downgrade (only if required)

Rollback Step 030 flag only:

```bash
cd backend
.venv/bin/alembic downgrade 0014_epistemic_memory_tables
```

Rollback through epistemic tables (drops `observation_ref`, `claim`, `evidence_link`):

**Warning:** Destructive — drops all shadow epistemic data. Only if no production dependency on collected claims.

Full rollback to Release 0.3 schema:

```bash
.venv/bin/alembic downgrade 0013_cache_namespace_v2_enabled
```

### Full artifact rollback

Deploy previous backend artifact (Release 0.3). Migrations `0014`/`0015` columns/tables remain but are unused by 0.3 code — harmless unless downgrade is also required.

## Kill-switch summary

| Concern | Action |
|---------|--------|
| Unexpected epistemic writes | `memory_shadow_write_enabled=false` |
| Unexpected memory_version bumps from shadow | Same — integration returns early when OFF |
| Cache v2 + shadow bump interaction | Set `cache_namespace_v2_enabled=false` or disable shadow first |
| Stale observation semantics (ADR-0001) | Disable shadow; revisit at Memory Integration cutover |
